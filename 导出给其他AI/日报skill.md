# 每日工作汇报（日报）

> 把这份文件发给其他 AI（Claude、ChatGPT 等），对它说：“以后我说『记一下』或『写日报』，就按这个来。”

## 核心原则：以文件为准，不靠聊天记录
聊天记录不可靠：会话不带时间，换了 API key 或账号后就读不到，别的 AI 也读不到。
所以每天的工作都记在「桌面\规划\YYYY-MM-DD 今日总结.md」这个文件里，**随做随记**。下班时只整理，不用回忆。

## 用法一：随手记（做完一个任务时）
我说「记一下」「记到日报」「这个做完了」时：
1. 打开当天的「YYYY-MM-DD 今日总结.md」，没有就新建。
2. 在「## 今日记录」下面追加一条，不改动已有内容：
   ```
   ### HH:MM 【项目名】一句话标题
   - 问题：原来哪里不对
   - 怎么做的：改了哪几处（分点）
   - 结果：测试结果 / 是否已发布 / 交给了谁
   - 待跟进：卡在哪、在等谁（没有就不写）
   ```
3. 内容从当前对话里取。数字只写对话里实际出现过的，不编。
4. 不能写文件的 AI：直接输出这一条，我自己贴进文件。
5. 回复一句“已记到今日总结”就行，不要长篇解释。

## 用法二：写日报（下班时）
只在我说「写日报」「总结今天」「我下班了」时才写。我还在干活时不要提前写。拿不准就问一句：“今天的活都做完了吗？”

### 第 1 步：按顺序找今天做了什么
1. **今日总结文件里的「今日记录」**：最可靠，优先用。
2. **项目的 git 记录或今天改过的文件**：补漏用，具体内容要问我确认。
3. **历史会话**：最后才用，换了 API key 可能读不到，不能当唯一来源。
4. 对不上、拿不准的，列出来问我，不要猜。

### 第 2 步：只挑项目工作
- **要写**：做了哪个项目、解决了什么问题、交付了什么、卡在哪里在等谁。
- **不写**：学习类问答、职业规划、闲聊、整理自己的文件。

### 第 3 步：在文件最上面写日报
```
## 日报（复制发给领导）
【日报】M月D日
1. 【项目名】：做了什么，结果是什么（已发布 / 已交付 / 已提交 IT）
2. 【项目名】：……

待跟进：卡在哪、在等谁（没有就不写这行）
明日计划：……（不知道就留“……”，提醒我自己补）
```
规则：
- 写结果，不写过程。用“已发布”“已交给 IT”，不用“研究了一下”。
- 同一个项目当天记了好几条，合成一行。
- 每个项目一到两行，领导 10 秒能看完。

### 第 4 步：保存并回复
- 日报放在文件最上面，「今日记录」留在下面当详细记录，不要删。
- 回复里把日报原文贴出来，方便我直接复制。

## 周五额外做一件事
把本周几天的今日总结合成周报：
```
【周报】M月D日–M月D日
本周工作：
1. 【项目】：做了什么，结果
遇到的问题：……
下周计划：……
```

## 写作要求
- 我是实习生，看不懂术语。用大白话，术语第一次出现时用一句话解释。
- 不要长篇大论。

【日报】11月5日
1. 产线 KPI 看板：核对新数据库 CGDL，CGDL 缺 29 条线的 OEE、区域层级和 C15 测试数据。已输出缺失数据清单和 IT 需求单，看板已切到 CGDL 并发布。

待跟进：等 IT 补齐 CGDL 数据后适配看板。
明日计划：……
